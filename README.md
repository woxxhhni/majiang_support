# majiang_support

四川麻将决策辅助引擎。

项目目标是先实现一个可验证的 **Sichuan Mahjong Decision Engine**：输入自己的手牌、定缺信息和局面阶段，输出推荐出牌、候选评分和可解释理由。后续再逐步加入外面牌统计、对手推断、风险收益模型和截图识别。

> V2 已实现网页原型：不做图像识别，不做自动代打，基于当前手牌评估平胡、七对、对对胡、清一色路线 EV。

## 已确认的 V1 规则口径

V1 按成都/四川血战到底的常见规则实现会影响决策引擎的部分：

- 只使用万、筒、条三门牌，共 108 张。
- 默认不使用东南西北中发白和花牌。
- 必须定缺，胡牌时不能持有定缺花色。
- 定缺花色尚未打完时，出牌候选只允许从缺门牌里选择。
- 可碰、可杠，不可吃。
- 血战到底中一家胡牌后其他玩家继续，但 V1 只做自己当前手牌的出牌建议，不做结算和多玩家续局模拟。
- V1 胡牌/向听先实现标准牌型：`4 副面子 + 1 对将`。七对、对对胡、清一色、龙七对放到 V2 EV 引擎。

## 快速使用

运行测试：

```bash
python -m pytest
```

命令行推荐出牌：

```bash
python -m majiang_support.app.cli recommend \
  --hand "1m 2m 3m 5m 6m 8m 8m 2p 3p 4p 6s 7s 9s 9s" \
  --missing p
```

输出会包含：

- 推荐出牌
- 是否触发定缺过滤
- 每张候选出牌的总分
- 打出后的向听数
- 有效进张剩余张数
- 保留结构评分
- 推荐理由

启动网页界面：

```bash
python -m majiang_support.app.web --host 127.0.0.1 --port 8765
```

然后打开：

```text
http://127.0.0.1:8765
```

网页支持：

- 点击牌池添加手牌
- 从牌池拖拽到手牌区
- 点击手牌移除
- 手牌区内拖拽调整顺序
- 一键排序
- 选择定缺
- 推荐定缺，并自动填入定缺下拉框
- 确认分析后直接在网页显示推荐出牌、候选评分和理由
- 上传游戏截图，先按区域裁剪，再用 `mahjong-detector` 做实验性识别
- 将截图里识别出的手牌确认后导入当前手牌

推荐定缺的 V1 逻辑是“放弃成本最低”：先看每门花色的张数，再看这门里是否已经有顺子、对子、刻子、两面搭子、中张连接等结构。张数少、孤张多、结构弱的一门更适合定缺。

截图识别当前是实验功能。流程是：

```text
整张截图
→ 裁剪底部手牌区域和桌面牌河区域
→ 调用 mahjong-detector 识别牌名
→ 在网页展示识别结果
→ 用户确认后导入手牌
```

第一版先锁定类似腾讯欢乐麻将横屏界面的相对坐标。由于不同机型、缩放、遮挡和动效会影响识别，导入前仍需要人工确认牌名。

出牌推荐当前使用更严格的优先级：

1. 先过滤定缺，缺门没打完时只在缺门牌里选择。
2. 分别评估平胡、七对、对对胡、清一色路线。
3. 每条路线计算 `EV = 完成概率 × 番数 × 阶段因子`。
4. 候选出牌优先按最高路线 EV 排序。
5. EV 接近时，再看向听数、有效进张、保留结构和弃牌自身价值。

有效进张会扣除已经打出的那张牌，避免把弃牌重新算进可摸剩余牌。

当前剩余牌口径：

```text
打出某张后的剩余数量 = 4 - 当前手牌中该牌数量
```

例如手里原本只有 1 张 5条，打出 5条后，牌墙里理论上仍可能剩 3 张 5条；如果手里原本有 2 张 1万，剩余 1万就是 2 张。后续接入已出牌和碰杠时，会在这个基础上继续扣除可见牌。

## 核心思路

项目按三层拆分：

1. 自己手牌最优决策
2. 对手牌型推断
3. 综合风险收益决策

第一阶段只做第 1 层：判断打哪张后，自己的牌最快、最舒服地胡。

输入示例：

```text
手牌：1万 2万 3万 5万 6万 8万 8万 2筒 3筒 4筒 东 东 白
规则：川麻，缺一门，血战到底

```

第一版必须完成：

- 川麻牌型表示
- 定缺过滤
- 向听数计算
- 有效进张计算
- 每张候选出牌评分
- 推荐最佳出牌并给出理由

## 第一阶段决策逻辑

### 1. 先看定缺

川麻第一原则：

```text
如果手里还有缺门牌，只能从缺门牌里选一张打。
```

例如定缺筒，手里还有 `2筒`、`7筒`，则候选出牌只在这两张里选择。

### 2. 每张牌都试着打一遍

对每个候选出牌模拟：

```text
当前手牌 - 候选出牌 = 13 张牌
```

然后给这副 13 张牌算分。

### 3. 优先看向听数

向听数越低越好：

```text
0 向听 = 听牌
1 向听 = 差一步听牌
2 向听 = 还差两步
```

打出后向听数最低的牌，优先级最高。

### 4. 再看有效进张

如果两张牌打出去后向听数一样，就比较有效进张数。

有效进张指摸到某张牌后，向听数下降，或者牌型结构明显变好。

### 5. 最后看搭子质量

同等条件下优先保留：

- 两面搭子，例如 `4万5万`
- 对子，例如 `8万8万`
- 中张连续，例如 `3万4万5万`

优先打掉：

- 孤张字牌
- 孤张幺九
- 边张搭子，例如 `1万2万`
- 坎张搭子，例如 `2万4万`
- 重复弱搭子

## V1 评分公式

第一版可使用简单评分：

```text
评分 = -100 × 向听数 + 有效进张数量 + 搭子质量分
```

伪代码：

```python
for tile in candidate_discards:
    hand_after_discard = hand.remove(tile)

    shanten = calculate_shanten(hand_after_discard)
    useful_tiles = calculate_effective_tiles(hand_after_discard)
    structure_score = evaluate_structure(hand_after_discard)

    total_score = (
        -100 * shanten
        + useful_tiles
        + structure_score
    )

choose_tile_with_highest_score()
```

一句话总结：

```text
第一阶段最佳出牌 = 打出去后向听数最低；
如果一样，选有效进张最多；
再一样，打掉结构价值最低的牌。
```

## 后续版本

### V2：牌型 EV 引擎

加入平胡、对对胡、清一色、七对、龙七对等候选路线，计算期望收益：

```text
EV = P(Hu) × Fan × StageFactor
```

其中：

- `P(Hu)`：胡牌概率估计
- `Fan`：番数
- `StageFactor`：局面阶段因子

候选路线示例：

```python
[
    "平胡",
    "对对胡",
    "清一色",
    "七对",
    "龙七对",
]
```

番数表可先配置为：

```python
{
    "平胡": 1,
    "对对胡": 2,
    "清一色": 4,
    "七对": 4,
    "龙七对": 8,
}
```

### V3：外面牌和风险折扣

维护牌池状态：

- 已打出的牌
- 碰杠牌
- 自己手牌
- 每张牌剩余数量
- 未知牌池估算

例如 `7万` 已经外面出现 3 张，则 `5万6万` 的价值下降，因为 `7万` 只剩 1 张。

### V4：对手牌型推断

先使用规则模型，不急着做复杂 AI：

- 对手长期不打某一门，可能说明这门是主攻方向。
- 对手早期打中张，可能说明该门不要，或者已经定缺该门。
- 对手碰了某一门很多牌，可能在做对对胡或清一色。
- 对手突然开始打安全牌，可能已经听牌。

最终对每张候选出牌计算点炮风险。

### V5：截图识别和实时推荐

在决策引擎稳定后再做：

- 手机或桌面截图识别手牌
- 自动识别牌桌区域
- 实时更新牌局状态
- 悬浮窗展示推荐结果

## 最终推荐格式

推荐结果应展示综合评分，而不是只给一张“最优牌”：

| 候选出牌 | 进攻评分 | 防守风险 | 番型潜力 | 综合建议 |
| --- | ---: | ---: | ---: | --- |
| 白 | 85 | 10 | 20 | 推荐 |
| 8万 | 72 | 35 | 40 | 可选 |
| 东 | 60 | 15 | 15 | 不推荐 |

综合评分可逐步演进为：

```text
综合评分 = 进攻价值 - 点炮风险 + 番型潜力
```

不同阶段调整权重：

- 早期：进攻权重大
- 中期：进攻和风险平衡
- 后期：防守权重大
